## IMPORTANT: design vs. product decisions
The design shows an UPLOADED video ("coffee-moment.mp4", duration 00:22, vertical). Product decision (memory: external hosting): NO uploads; a work is a link to a public TikTok/Instagram post. Therefore map the left card as follows (propose; the Figma does not show these):
- Preview area: `submissions.thumbnailUrl` (TikTok oEmbed) on the 720x324 elevated surface; fallback to the challenge cover art (as drawn) when null.
- Replace row "ფაილი" with the post link: label `ბმული` (needs copy; Figma has none) → `submissions.mediaUrl` opening in a new tab; and add rows for platform (`submissions.platform` tiktok|instagram), handle (`submissions.handle`, e.g. `@nino.creates`), caption (`submissions.caption`).
- "ხანგრძლივობა" (duration) and "ფორმატი: ვერტიკალური · 22 წამი" have NO data (no duration stored; platforms' public preview might not give it) → drop or show "unavailable", never 0.
- The `შეფასება` checklist: card 1 `QR ვიზიტი / დადასტურებულია` = does a `checkins` row exist for the QR of the challenge's `visit_qr` mission for this user (only meaningful for `kind="visit"` challenges, where the video mission unlocks after the QR visit via `missions.unlockAfterMissionId`). Card 2 ("ფორმატი") has no equivalent → replace with the hashtag check: required tags come from `challenges.hashtags` (e.g. `#BeFamous #SecretCoffee`), compared to `submissions.caption`; when missing show the system note `missing:#Tag` (per-tag). No copy in Figma for this.
- Metrics block (views/likes/comments) is not in this design; if added, use `social_posts` by `submissionId`: status (found|ownership_check|verified|unavailable|metrics_unavailable|refresh_failed), `metrics {views,likes,comments}` nullable (null = unknown, NOT 0), `metricsSource`, `lastSyncedAt`. Always show source + timestamp.
- Participant info: `users.name`, challenge title in subtitle.
- Already reviewed submissions (status ≠ pending): disable/hide the three buttons and show `reviewNote`, `reviewedAt` (not designed).

## Dynamic data → DB mapping
Participant = `users.name`; challenge = `challenges.titleKa`; mission = `submissions.missionId`; status/reviewNote/reviewedAt/reviewerId = `submissions.*`. Server action: `reviewSubmission(submissionId, reviewerId, "approved"|"revision"|"rejected", note?)` in `src/lib/progress.ts` — it updates the submission, completes the mission + sets linked `social_posts.status="verified"` + notification `submission_approved` on approve, or resets the mission to `in_progress` + notification `submission_revision` / `submission_rejected` (with `note`) otherwise.
