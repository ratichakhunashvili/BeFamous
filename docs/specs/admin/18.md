## Dynamic data → DB mapping
- Card per `challenges` (title). Rows = `participations` (userId, challengeId, joinedAt) joined to the participant's work for the mission:
  - მონაწილე = `users.name`
  - მისია = `missions.type`: `upload` / `social_post` → `ვიდეო ნამუშევარი` (a submission); `visit_qr` → `QR ვიზიტი` (a `checkins` row via `qr_codes.missionId`); `invite` → no copy in design (needs new label).
  - სტატუსი: submission `status` — `pending` → `შესამოწმებელი`; `approved` → `დადასტურებული`. QR visit that exists = `დადასტურებული`. Labels for `draft`, `revision`, `rejected` are NOT in this design (propose: `შესწორება მოთხოვნილია` (copy from 41) / `უარყოფილი` (copy from 42); draft hidden from admin).
  - დრო: relative time from `submissions.createdAt` / `checkins.createdAt` (`დღეს` = today, `გუშინ` = yesterday; older formats not designed, in Asia/Tbilisi).
- Data gap: the row ↔ submission link; row id for the route must be `submissions.id` (QR rows have no review page).
