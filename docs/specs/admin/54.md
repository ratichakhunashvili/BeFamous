## Mapping to the actual model (no per-business team)
Reinterpret as **admin access**: list of users with `users.role = 'admin'` (+ pending grants). Roles owner/editor/reviewer have **no DB column** — only `user|admin`. Recommended: single role "ადმინი" (admin); drop the role segment or show fixed label. Columns:
- name/email: `users.name`, `users.email`
- state: `აქტიური` = existing user with role admin; `მოწვეული` has no equivalent (no pending-invite store) — either drop, or add a small `admin_invites(email, createdAt)` table; otherwise granting is immediate for an existing account email.
Intended actions (NOT designed, proposed): input email + button "წვდომის მიცემა" -> `update users set role='admin' where email=…` (must be existing user; else error), per-row "წვდომის მოხსნა" -> `role='user'`. Guards: cannot remove own admin or the last admin; `users.sessionVersion++` on demotion; write `auditLog` (`action:'admin_grant'|'admin_revoke'`, `target:userId`).
Button destination not specified (likely dashboard) — flag.
