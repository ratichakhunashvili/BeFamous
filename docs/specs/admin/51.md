## Data mapping (all aggregated; min group size rule: hide groups with n < k, k to be decided, e.g. 5, per the copy "მცირე ჯგუფების პირადი მონაცემები არ გამოჩნდება")
- **ახალი მონაწილეები / დაბრუნებული მონაწილეები** (84 / 44, 66% / 34%): per campaign+period, participants whose first-ever `participations.joined_at` falls in the period = new; participants in period who have an earlier participation in any other challenge = returning. `WITH p AS (SELECT user_id, MIN(joined_at) first FROM participations GROUP BY 1) SELECT COUNT(*) FILTER (WHERE first >= :from) new, COUNT(*) FILTER (WHERE first < :from) returning FROM participations x JOIN p USING(user_id) WHERE x.challenge_id=:c AND x.joined_at in range`. Percent = share of that total. (Sample 84+44=128 ≠ 428 participants on screen 20: mock.)
- **გეოგრაფია** (82% თბილისი): `SELECT users.city, COUNT(*) ... GROUP BY city` over the campaign's participants. Source `users.city` is free text/nullable, self-reported; null city = "unknown", not counted as a city. **No location-consent field exists** in schema although copy says "location is used only with consent": flag; either add a consent flag or reword copy to "self-reported city".
- **ყავისა და კულინარიის ინტერესი** (96, 75%): `COUNT(DISTINCT user_id)` from `user_interests` joined `interests` (slug for coffee/cooking) for campaign participants. Percent = 96/128 = 75% (denominator is the 128 new+returning total, not 428).
- **NO DATA SOURCE**: age, gender, device, reach/impressions, follower demographics, any platform audience data (no such columns; integrations unvalidated). If the product later wants them, show `მიუწვდომელია`, never invented numbers. None appear in this frame's copy, so only the above rows are required.
